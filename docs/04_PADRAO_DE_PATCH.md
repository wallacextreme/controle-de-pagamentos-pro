# PADRÃO OFICIAL DE ALTERAÇÕES (MODO PATCH)

## Objetivo

Toda Inteligência Artificial deverá modificar este projeto utilizando exclusivamente o modo PATCH.

É proibido reescrever arquivos completos quando apenas parte do código precisa ser alterada.

---

# REGRA 1

Nunca reescrever o arquivo inteiro.

Modificar somente os trechos necessários.

---

# REGRA 2

Antes de escrever qualquer código:

Analisar completamente a solicitação.

Identificar quais funções realmente precisam ser alteradas.

---

# REGRA 3

Sempre informar:

- quais funções serão alteradas;
- por que serão alteradas;
- impacto esperado.

---

# REGRA 4

Nunca alterar funções que não estejam relacionadas diretamente à solicitação.

---

# REGRA 5

Sempre preservar:

- comentários existentes;
- nomes de funções;
- nomes de variáveis;
- organização atual do projeto.

---

# REGRA 6

Sempre criar novas funções quando possível.

Evitar modificar funções antigas.

---

# REGRA 7

Nunca remover código existente.

Caso um trecho deixe de ser utilizado, solicitar autorização antes de removê-lo.

---

# REGRA 8

Sempre indicar exatamente onde o novo código deverá ser inserido.

Exemplo:

Após a função X.

Antes da função Y.

Dentro do evento Z.

---

# REGRA 9

Quando alterar uma função existente:

Mostrar:

FUNÇÃO ORIGINAL

FUNÇÃO ALTERADA

Explicar exatamente o que mudou.

---

# REGRA 10

Nunca alterar comportamento existente sem autorização.

---

# REGRA 11

Sempre manter retrocompatibilidade.

Toda alteração deve funcionar com os dados já existentes.

---

# REGRA 12

Ao finalizar qualquer implementação apresentar a seguinte validação:

☐ Nenhuma função removida.

☐ Nenhum HTML removido.

☐ Nenhum CSS removido.

☐ Nenhuma variável removida.

☐ Nenhum banco apagado.

☐ Nenhum registro perdido.

☐ Retrocompatibilidade preservada.

☐ Funcionalidades existentes preservadas.

Somente considerar a tarefa concluída após validar todos os itens.
